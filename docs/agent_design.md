# 智能体设计文档（对应 hello-agents 第 1/2/3/6 章）

## 一、智能体是什么（第1章）

智能体 = **大语言模型（大脑） + 规划（思考/推理循环） + 记忆（短期/长期） + 工具（与外部世界连通）**。
本项目严格按此四要素构建：

| 要素 | 实现 |
|---|---|
| LLM | agent/llm.py（OpenAI 兼容客户端，可切换任意模型） |
| 规划 | agent/agent_core.py（ReAct / Plan-and-Solve / Reflection 三种推理循环） |
| 记忆 | agent/memory.py（会话窗口短期记忆 + 用户画像长期记忆 + RAG 知识检索） |
| 工具 | agent/tools.py（kb_search / icer_calc / adr_quick / law_lookup / template_list / checklist_router） |

**能力边界**（本书强调的 Agent 三大问题，本项目的对策）：
1. 幻觉 → SYSTEM 强制"基于工具结果回答，禁止编造法规数据"+ 来源标注 + Reflection 自我检查
2. 推理循环 → MAX_ROUNDS=4 上限 + 无工具调用即终止
3. 工具误用 → 结构化参数协议 + 执行失败注入可读错误 + 工具结果截断防上下文爆炸

## 二、发展脉络简史（第2章）

符号主义推理 → 专家系统 → 互联网信息智能体 → 大模型时代：
- **软件工程式 Agent**（Dify/Coze/n8n）：流程驱动，LLM 作数据处理后端
- **AI Native Agent**（本书倡导）：推理驱动，LLM 是决策核心
本项目的引擎（agent_core.py 推理循环 + 工具协议）属于 **AI Native** 路线；同时保留"软件工程式"的稳定交互服务（自查清单、模板）作为确定性组件，二者互补。

## 三、大语言模型基础（第3章）：模型选择与参数指南

| 场景 | 模型建议 | temperature |
|---|---|---|
| 法规/合规问答（需要严谨） | deepseek-chat / gpt-4o-mini | 0.1-0.3（默认0.3） |
| 用药咨询、综合建议 | qwen-plus / glm-4-flash | 0.3-0.5 |
| 头脑风暴、培训材料生成 | 任意创意型模型 | 0.6-0.8 |
| 本地离线（无 API） | Ollama qwen2.5:7b | 0.3 |

**防幻觉三条铁律**（已写入 SYSTEM）：① 只基于工具结果与知识库；② 不确定时明说"以现行法规为准"；③ 用药回答必附安全提示。

## 四、为什么自研框架而不是 LangChain（第6章）

本书观点与项目实践的共鸣：
1. **依赖零成本**：纯标准库（urllib/tkinter/http.server），无 pip 依赖、无版本漂移（全书主线）
2. **透明可观测**：每次回答返回 trace 思考轨迹，观看每一步工具调用（可解释性）
3. **深度定制**：药事领域特殊工具（ICER 计算器、麻精五专自查）可精确实现
4. **教学友好**：全项目约 3000 行主代码，任何人可读完
对应取舍：失去 LangChain 生态便利，但对单领域垂直 Agent 而言收益大于成本。
